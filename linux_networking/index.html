La idea

Cuatro datos y ya está

Para que un equipo hable con el resto del mundo hacen falta cuatro cosas, ni una más. Todo lo que sigue en esta guía son formas de leer esas cuatro cosas y de comprobar en cuál se ha roto algo.

Nombre del equipo

Dos familias de comandos, no una. Las órdenes antiguas (ifconfig, route, netstat, arp) vienen del paquete net-tools y están en desuso: en muchas distribuciones ni siquiera se instalan. Las modernas (ip, ss) vienen de iproute2 y están siempre. El examen espera que conozcas las dos y sepas cuál sustituye a cuál.

Guía interactiva

Los comandos, uno a uno

Cada botón es un comando real con la salida que produce. Filtra por familia si buscas algo concreto: lo importante no es la salida en sí, sino en qué te tienes que fijar de ella.

terminal

        


        

        

      


      

        Todos son de solo lectura. Ninguno de estos comandos cambia nada en el sistema, así que puedes ejecutarlos sin miedo y sin sudo. Los que sí modifican la red (ip addr add, ip link set) aparecen más abajo, señalados.
      

    


    
    

      
Campo a campo

      
Leer la salida de ip a

      

        
Es la salida que más veces vas a mirar y la que más asusta la primera vez. En realidad son dos líneas útiles por interfaz: la del enlace (nombre, estado, MAC) y la de la dirección (IP, prefijo, difusión).

      


      

        

          inet192.168.1.50/24brd192.168.1.255scope globalenp0s3
        

        
inet es IPv4 (inet6 sería IPv6). El /24 dice que los 24 primeros bits son la parte de red: eso es la máscara 255.255.255.0 escrita de otra forma. scope global significa que la dirección vale fuera de la propia máquina; scope host es solo interna, como 127.0.0.1.

      


      

        

          
Lo que vesQué significa

          
            
1: lo:Interfaz número 1, la de loopback. Siempre existe, siempre es 127.0.0.1 y no sale de la máquina: sirve para que los programas locales se hablen entre sí.

            
2: enp0s3:La tarjeta de red real. Los nombres modernos describen dónde está enchufada la tarjeta (en = ethernet, wl = wifi); los antiguos eran eth0, wlan0.

            
<BROADCAST,MULTICAST,UP,LOWER_UP>Banderas del enlace. UP = el sistema la ha activado; LOWER_UP = hay cable conectado o wifi asociada. Si falta LOWER_UP, el problema es físico.

            
state UP · state DOWNEl resumen del estado. lo aparece como UNKNOWN y es normal.

            
mtu 1500Tamaño máximo de paquete en bytes. 1500 es lo normal en ethernet.

            
link/ether 08:00:27:1c:4f:aaLa dirección MAC: identifica la tarjeta dentro de la red local. Es lo que ifconfig llama ether o HWaddr.

            
inet 192.168.1.50/24La dirección IPv4 y su prefijo. Este es el dato que buscas el 90 % de las veces.

            
brd 192.168.1.255Dirección de difusión: la que alcanza a todos los equipos de esa red a la vez.

            
inet6 fe80::…/64Dirección IPv6. Las que empiezan por fe80:: son de enlace local: se autogeneran y no salen de la red local.

            
valid_lft 84523secLo que queda del préstamo DHCP. Si pone forever, la dirección es fija.

            
dynamicLa dirección la ha dado un servidor DHCP. Sin esa palabra, está configurada a mano.

          
        

      


      

        Cuando solo quieres el dato. ip -br a imprime una línea por interfaz, y hostname -I imprime únicamente las direcciones, sin nada alrededor: es la forma cómoda de meter la IP en un script.
      

    


    
    

      
Lo viejo y lo nuevo

      
ifconfig frente a ip

      

        
ifconfig (interface configurator) fue durante veinte años el comando de red de Unix. Hoy está sin mantenimiento: no entiende varias direcciones por interfaz, ni las etiquetas modernas del kernel, ni buena parte de IPv6. Su sustituto es ip, un único comando con subórdenes: ip addr, ip link, ip route, ip neigh.

        
Sigue apareciendo en el examen, en documentación antigua y en máquinas heredadas, así que conviene saber traducir de uno a otro.

      


      

        

          
Antiguo · net-toolsModerno · iproute2Para qué

          
            
ifconfigip addr show · ip aVer las direcciones de todas las interfaces.

            
ifconfig -aip aIncluir también las interfaces inactivas. ip ya las muestra siempre.

            
ifconfig eth0ip a show eth0Ver una interfaz concreta.

            
ifconfig eth0 up · downip link set eth0 up · downActivar o desactivar una interfaz. Requiere root.

            
ifconfig eth0 10.0.0.5 netmask 255.255.255.0ip addr add 10.0.0.5/24 dev eth0Asignar una dirección a mano. Requiere root.

            
route -nip route show · ip rVer la tabla de rutas.

            
route add default gw 192.168.1.1ip route add default via 192.168.1.1Fijar la puerta de enlace. Requiere root.

            
arp -aip neigh show · ip nVer los vecinos conocidos de la red local.

        «ifconfig: no se encontró la orden». No es un fallo del sistema: es que net-tools no está instalado, cosa normal en Debian 12, Ubuntu moderno o Fedora. Se arregla con sudo apt install net-tools (o dnf install net-tools), pero casi siempre la respuesta correcta es escribir ip a en su lugar.

        Ni uno ni otro guardan nada. Todo lo que cambies con ip o ifconfig vive en la memoria del kernel y desaparece al reiniciar. La configuración permanente está en otro sitio según la distribución: NetworkManager (nmcli), systemd-networkd, /etc/network/interfaces en Debian clásico o /etc/netplan/ en Ubuntu.
      

    


    
    

      
Por dónde sale

      
La tabla de rutas

      

        
Tener IP no basta: cuando el kernel va a enviar un paquete, mira esta tabla para decidir por qué interfaz sale y a quién se lo entrega primero. La regla es simple: gana la ruta más específica, y si ninguna encaja, se usa la de por defecto.

      


      

        

          
ip route show


$ ip route show
default via 192.168.1.1 dev enp0s3 proto dhcp metric 100
192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.50 metric 100

        

        
Dos líneas y dos ideas. La segunda dice «lo que sea de 192.168.1.0/24 está aquí al lado, lo entrego yo directamente». La primera dice «cualquier otra cosa, dásela a 192.168.1.1»: eso es la puerta de enlace, el router.


        

          
default via
La puerta de enlace. Si esta línea no existe, tendrás red local pero no Internet.

          
dev enp0s3
Por qué interfaz se envía.

          
proto dhcp · kernel
Quién puso la ruta: el cliente DHCP o el propio kernel al configurar la dirección.

          
src 192.168.1.50
Con qué dirección de origen saldrán los paquetes.

          
metric 100
Coste. Si hay dos rutas equivalentes, gana la de métrica más baja: así el cable gana al wifi.

        

      


      

        Para saber por dónde saldría un paquete concreto no hace falta interpretar la tabla entera: ip route get 1.1.1.1 te responde con la ruta que se usaría, la interfaz y la IP de origen. Es la forma rápida de comprobar si el tráfico sale por donde crees.
      


      

        Estos sí modifican (requieren root). ip link set enp0s3 up activa la interfaz, ip addr add 192.168.1.60/24 dev enp0s3 añade una dirección y ip route add default via 192.168.1.1 fija la salida. Se deshacen con down, del y route del, y se pierden al reiniciar.
      

    


    
    

      
De nombre a número

      
Nombres y DNS

      

        
Las máquinas se hablan por IP; las personas escribimos nombres. El DNS es el servicio que traduce www.lpi.org en 104.22.28.145. Antes de preguntar a nadie, el sistema mira su propia chuleta local.

      


      

        

          
FicheroQué contiene

          
            
/etc/hostsTraducciones fijas escritas a mano, que ganan al DNS. Siempre trae al menos 127.0.0.1 localhost. Es donde mirar cuando un nombre resuelve a algo imposible.

            
/etc/resolv.confA qué servidores DNS preguntar: líneas nameserver 192.168.1.1. Suele generarlo NetworkManager o systemd-resolved, así que editarlo a mano rara vez dura.

            
/etc/nsswitch.confEl orden de consulta. La línea hosts: files dns es la que dice «primero /etc/hosts, luego el DNS».

            
/etc/hostnameEl nombre de este equipo. Se consulta con hostname y se cambia con hostnamectl set-hostname nombre.

          
        

      


      
Tres comandos para preguntar lo mismo

      

        

          
ComandoCuándo usarlo

          
            
host lpi.orgRespuesta en una línea, legible. Lo primero que probar.

            
dig lpi.orgRespuesta completa: secciones, tipo de registro, TTL y qué servidor contestó. Con +short imprime solo la IP.

            
nslookup lpi.orgEl clásico, también en Windows. Funciona, pero dig y host se consideran preferibles en Linux.

          
        

      


      

        Truco de diagnóstico. Si ping 8.8.8.8 funciona y ping google.com falla con «Nombre o servicio desconocido», la red está bien y lo que está roto es el DNS: mira /etc/resolv.conf. Es el fallo más frecuente y el que más se pregunta.
      

    


    
    

      
Cuando no hay red

      
La escalera de diagnóstico

      

        
«No tengo Internet» son cinco problemas distintos. Se prueban en orden, de dentro hacia fuera, y el primer escalón que falla señala la causa.

      


      

        

          

            

              ip link show
              
¿Existe la interfaz y está UP? Si está DOWN: actívala con ip link set … up. Si falta LOWER_UP, el cable o el wifi no están conectados.

            

          

          

            

              ip addr show
              
¿Tiene una IP que no sea la de loopback? Sin inet, o con una 169.254.x.x, el DHCP no ha respondido.

            

          

          

            

              ping -c 3 192.168.1.1
              
¿Contesta la puerta de enlace? Si no, el problema está en la red local: cable, wifi, máscara mal puesta o el propio router.

            

          

          

            

              ping -c 3 8.8.8.8
              
¿Se sale a Internet por IP? Si el router responde pero esto no, falta la ruta por defecto (ip route) o el corte está más arriba: traceroute -n 8.8.8.8 enseña dónde.

            

          

          

            

              ping -c 3 google.com
              
¿Se resuelven los nombres? Si los cuatro pasos anteriores van y este falla, es el DNS: /etc/resolv.conf, y compruébalo con dig +short google.com.

            

          

        

      


      

        ping 127.0.0.1 es un caso aparte. No prueba la red: prueba que la pila TCP/IP del propio sistema funciona. Si eso falla, no mires el cable. Y ojo, hay servidores que ignoran los ping por política: que uno no conteste no siempre significa que esté caído.
      


      

        

          
SíntomaSospechoso

          
            
Ping por IP sí, por nombre noDNS. /etc/resolv.conf.

            
La IP empieza por 169.254.Autoconfiguración: no hubo respuesta del DHCP.

            
La puerta de enlace responde, Internet noFalta la ruta default, o el corte está aguas arriba.

            
Un servicio local no acepta conexionesMira si escucha: ss -tuln | grep :puerto. Si escucha en 127.0.0.1, solo acepta conexiones de la propia máquina.

            
Nada responde, ni el propio equipoping 127.0.0.1: si falla, el problema es la configuración del sistema, no la red.
